# 数据授权分组与细粒度权限 — 整合研究（2026-09-22）

> 背景：spec §7 四维权限（职级/公司/数据域/事业部）暂缓至今；用户裁定知识体系收官后启动本研究。目标：给出分阶段落地方案与决策问题清单。
> 姊妹文档：`2026-09-20-dba-workorder-readonly-account.md`（已完成的只读收紧）。

## 一、现状盘点（全部实测核实）

| 层 | 现状 | 授权粒度 |
|---|---|---|
| DWS 账号 | 单一 `aiuser`（只读已收紧：写授权全撤/CREATE 全禁） | **无分组**——谁能登录谁就能 SELECT 全部 2276 张表 |
| 网关 | `scope_group` 全链路预留：POST /api/tasks 收 → tasks 表存 → 每任务 `resolveDbAccount(scope_group)` 解析 DB 账号；**未知组硬报错**（宁失败不静默降级） | 账号级（待映射表填充） |
| UI/BFF | users 表无组概念；/api/ask 不传 scope_group | 无 |
| 知识域边界 | skill 路由 + 域外拒答（软边界，模型层） | 域级·软约束 |
| 审计 | user/session/run 全链路关联（spec §7 底线 3 已满足） | — |

**差距一句话**：软边界靠模型自觉（可被诱导绕过），DB 层是"一个账号看全部"——用户 A 诱导 agent 查用户 B 部门的数据，今天只有知识层在挡。

## 二、方案选项对比

| 方案 | 粒度 | 原理 | 落地成本 | 结论 |
|---|---|---|---|---|
| **A. 多账号分组** | 表/Schema 级 | 每组建一个受限只读 DWS 账号（授权=该组可见的 schema/表清单）；网关 ACCOUNTS 表加条目即接通（**代码零改动**） | DBA 每组建号+授权；组多则账号多 | ✅ **P1 首选**——接口全就绪 |
| **B. 过滤视图分组** | 行级（事业部/组织） | 每组建"过滤视图集"（视图内嵌 `WHERE node_desc2='瓷砖事业部'` 类条件），组账号只授权视图不授权基表 | DBA 建视图集并随表结构维护 | ✅ P2——事业部行级隔离的正路 |
| **C. GaussDB RLS** | 行级（任意维度） | 表挂 POLICY + 会话变量（`SET app.scope=...`），MCP 连接注入 | 需逐表开 ROW LEVEL SECURITY + 策略；GaussDB 兼容性需 spike；全部大表性能影响未知 | ⏸ P3——最细但最重，试点规模不值得 |
| D. 应用层注入 WHERE | — | 网关改写 agent SQL 加过滤 | — | ❌ 否决：agent 自由生成 SQL（子查询/CTE/UNION），改写不可靠，假安全感比没有更危险 |

## 三、关键设计问题：分组维度（决定 DBA 怎么建号）

四维（职级/公司/数据域/事业部）不必同时做。试点 5 人 + 6 个已覆盖域，现实选项：

| 维度 | 组形态 | DBA 授权单元 | 适配场景 |
|---|---|---|---|
| **数据域**（推荐 P1） | 财务组/库存组/应收组…（可多选） | 每组=该域表清单（我们有：skills 路由节已固化各域主表） | "财务的人只能问费用成本" |
| 事业部（P2，走视图） | 瓷砖组/卫浴组… | 过滤视图（node_desc 条件） | "卫浴的人查不到瓷砖明细" |
| 公司/职级 | 暂缓 | — | 无试点需求前不做 |

**数据域分组的坑（提前预警）**：六域共表严重（dm schema 多域共用、跨域维表 dwrdim/dwimd 全员要用）。按表清单精确授权 = DBA 要维护 6 份表清单且随知识扩域更新；妥协选项 = **两级组**（`base`=维表+全员共用表，`domain-x`=域事实表，账号同时授两组的并集——DWS 授权天然是并集，可行）。

## 四、端到端接线（P1 方案 A 全景）

```
管理后台用户页：给用户选组（users.scope_group，默认 base）
  → BFF /api/ask 透传 scope_group（一处改动）
  → 网关 resolveDbAccount 查 ACCOUNTS（加条目，零代码）
  → dsh spawn 注入该组的 DWS_USER/DWS_PASSWORD（机制已存在）
  → 该组账号 SELECT 越组表 = DB 直接权限错 → agent 看到"无权限"如实转述
```
配套：域外拒答话术升级（"您的权限组不含此域"）；审计维度加 scope_group（tasks 表已有字段，报表补一列）。

## 五、分阶段建议

| 阶段 | 内容 | 前置 |
|---|---|---|
| **P1** | 数据域分组：DBA 建 base+域账号（建议先 2 个域试点：库存+财务）→ 网关映射 → BFF/UI 组字段 | 用户定分组清单；DBA 工单 |
| **P2** | 事业部行级：过滤视图集 + 组账号授权视图 | P1 稳定 + 有真实跨事业部隔离需求 |
| **P3** | RLS/职级/公司维 | 有不可用视图满足的需求再评估 |

## 六、决策问题（待用户裁定）

1. **P1 分组维度确认**：按数据域？先开哪几域的组（建议库存+财务两个试点）？
2. **组与用户关系**：一人一组（简单）还是一人多组（base+多域并集，管理后台多选）？建议 P1 一人一组、组内含 base 并集。
3. **DBA 工单时机**：表清单我们出（从 skills 路由节导出），还是 DBA 自行裁定宽窄？
4. P2 事业部隔离现在有没有真实试点需求（决定要不要排期）？
