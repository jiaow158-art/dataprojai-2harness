# 对话页 UI 重设计：结论优先 + 证据下钻

## 目标

在不改变现有核心功能和 API 的前提下，将对话页从“深色聊天 + SQL 堆叠”升级为浅色企业经营大脑风格。用户首先看到业务结论、关键指标和可执行建议；SQL、耗时和数据血缘保留在默认折叠的技术详情中。

## 不可变边界

- 不修改 API 路径、请求参数、响应结构、SSE 事件协议或后端查询逻辑。
- 不修改登录、权限、会话持久化、问答、追问、报告查看、反馈和重试的业务行为。
- 只在前端增加展示适配与组件拆分；已有字段缺失时显示诚实的“暂无数据/无法判断”，不推断新结论。

## 视觉方向

- 参考用户提供的“东鹏经营大脑”截图：白色主背景、浅蓝灰工作区、蓝色主色、红橙告警、青绿正向状态。
- 左侧固定导航 + 顶部品牌/搜索/通知/用户区 + 中央对话工作区；保留现有产品入口。
- 使用白色圆角卡片、细边框和轻阴影建立层级，减少大面积深色和等宽字体。
- 反馈、重试、发送、查看详情等控件可借鉴 Uiverse 的微交互和按钮结构，但以本地 CSS/React 实现，不引入远程脚本、外部运行时或不可审计依赖。

## 回答结构

1. `AnswerSummaryCard`：状态标签、结论标题、摘要文案。
2. `MetricStrip`：从现有回答数据映射 2–4 个关键指标；缺失字段不造数据。
3. `EvidenceList`：原因/证据条目，点击展开已有图表、明细或数据范围。
4. `ActionPanel`：建议动作和现有追问入口。
5. `FreshnessBadge`：已有数据日期、更新时间、确认状态。
6. `TechnicalDetails`：默认折叠，展示 SQL、查询数量、耗时、数据血缘和原始错误信息。

## 状态与错误

- 成功：蓝色/青绿色状态，突出结论。
- 需要关注：橙色或红色标签，突出风险指标。
- 数据不足：中性提示，说明缺失范围。
- 失败：业务化文案 + 重试按钮；技术错误进入 TechnicalDetails，底层错误处理不变。
- 流式过程中：保留现有阶段事件和取消/超时行为，前端以步骤条或骨架卡片呈现。

## 响应式与可访问性

- 桌面端采用导航、主内容、辅助信息的弹性布局；窄屏时侧栏折叠，回答卡片单列堆叠。
- 所有操作按钮有明确中文标签、键盘焦点和 `aria-expanded`/`aria-label`；颜色不是唯一状态表达。
- SQL 代码区域支持复制和横向滚动，不影响业务内容阅读。

## 数据流

现有 API/SSE → 现有 hooks/types → 新的展示适配函数 → 结论卡/证据/技术详情组件。适配函数只读取已有字段，组件不直接发起新的 API 请求。

## 验收标准

- 默认视图不出现连续 SQL 文本；SQL 仅在用户展开技术详情后出现。
- 同一响应下，问答、追问、报告、反馈、重试请求与改造前行为一致。
- 成功、流式、数据不足、失败四类状态均有清晰视觉呈现。
- 1440px 桌面与 390px 移动宽度无横向溢出，核心操作可用。
- 现有前端测试通过，并新增回答渲染与技术详情折叠的组件测试。
