# dsh 引擎接入 · M3 内部白名单试点 — 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**T0 裁定（用户 2026-09-20 确认）**：部署=**方案 A**（本机 Windows 常驻，"我这边跑成功先"）；其余按建议默认（首批白名单 ≤5 人名单于 T2 建号时定、6 域全开、验收 2-4 周/≥50 任务/失败率<10% 且逐例可归因、余额阈值建脚本后再定）；服务器 Linux 移植与 M4 一起做。
**管理后台路线裁定（同日）**：审计查询进 M3（T3.5）；管理后台 v1（用户/审计/统计界面）= M4；语义/域知识管理+版本化 = M4+，以"git 版本内核 + eval 回归门控"为前提（裸 UI 编辑不过回归=事故源）。

**Goal:** 把已过全部前置的系统开放给**白名单内部员工**真实使用（spec §12 M3 行），验证"真实任务持续可用、失败可追踪可复现"，产出试点报告与 M4 放行材料。

**前置状态（2026-09-20）**：M0/M1/M2 全 GO；M3 前置清单 5/5 销账（UI v1 交付验收、E-5 读围栏、DBA 只读、金点子轮 10/10 引擎全对、otd 场景补齐）。spec §7 三底线为试点边界。

**Architecture:** 现有全栈原样上线（engine-gateway + dataplat-ui BFF/前端 + Docker 沙箱 + dsh 0.1.2-rc.1），试点只做**部署化、账号化、观测化、规范化**四件事，不改产品代码（试点期发现的问题走记录→修复→回归，不热改）。

**Tech Stack:** 现有栈零新增；部署脚本（Windows 常驻或 Linux 移植，T1 裁定）。

### Task 0: 试点方案定稿（需用户参与——本计划的输入）

- [ ] 白名单名单与规模（建议首批 ≤5 人：提出建议名单，用户裁定）
- [ ] **部署位置裁定**：
  - 方案 A（快）：本机 Windows 常驻化（pm2/nssm 守护网关+BFF+前端静态托管，防火墙开放 BFF 端口给内网）——同事访问 `http://<本机IP>:58090`；零移植成本，风险=本机即生产
  - 方案 B（正）：服务器 Linux 移植（run_in_sandbox.sh 去 winpath、profile 脚本路径适配、systemd 三服务）——正路但多一轮适配+验证工作量
  - 建议A先行试点、B在 M4 正式化时做（试点目的是验证业务价值与稳定性，不是验证部署形态）
- [ ] 数据授权范围确认（=6 覆盖域全部事实表？还是再收窄？三底线第 1 条要求"员工确实有权查看"）
- [ ] 试点时长与验收数字（建议：2-4 周；≥50 个真实任务；引擎侧失败率 <10% 且每例可归因；用户主观可用性反馈收集）
- [ ] DeepSeek 余额策略（402 曾两次中断测试）：预算上限 + 低于阈值告警方式（谁看、怎么提醒）
- [ ] **dsh 0.1.2-rc.1 预览版风险接受记录在案**（spec §12 M3 行要求）：固定版本不追新，升级窗口在 M4

### Task 1: 部署化（按 T0 裁定执行）

- [ ] 方案 A：pm2（或 nssm）守护 engine-gateway / UI BFF；web/ `npm run build` 产物由 BFF 静态托管（dataplat-ui 已具备）；开机自启；防火墙规则仅对内网网段开放 BFF 端口
- [ ] 强随机 AUTH_TOKEN 替换 manual-token（网关与 BFF 同步换）；生产端口沿用 58080/58090
- [ ] 验证：外部同事视角访问链路通（登录→提问→报告）；断电重启后三服务自愈
- [ ] （方案 B 时：沙箱脚本 Linux 适配 + 红队复跑 + e2e shot 基线复验）

### Task 2: 账号与白名单

- [ ] `admin:add` 建 N 个白名单账号（用户名=工号或姓名拼音，密码首登可改——v1 无改密功能则分发一次性强密码+提醒）

- [ ] 验证：白名单外无法登录（无账号即无门）；测试账号 tester-a/b 清理

### Task 3: 观测与追踪（失败可追踪、可复现——M3 放行条件）

- [ ] `scripts/pilot-daily.mjs`（新，网关 SQLite 只读）：每日摘要——任务量/成功率/失败分类分布/tokens 消耗/余额余量估算/活跃用户；输出 markdown 到 `eval_results/pilot/`
- [ ] 失败复现路径 SOP：run_id → 网关 DB 查 attempt/error_code/事件流 → eval 复跑（--idx 对应场景或 ask.py 重放原问题）
