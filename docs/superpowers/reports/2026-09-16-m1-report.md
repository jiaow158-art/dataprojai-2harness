## M1 期间的关键实测发现与修复

1. **S3 spike（决定性）**：dsh SDK 同 sessionId 跨进程**不恢复且确定性撞 id**（服务端会话表纯内存）→ 网关侧每次 spawn 用 `gw-<sid>-a<attempt>-<nonce>` 唯一 id + S2 全量历史注入（findings §5.5）
2. **SDK 无取消方法**（协议仅 initialize/prompt/shutdown 三法）→ 超时/取消 = kill 进程树
3. **spawn env 契约**：少一个 M0_* 变量插件树即挂（-32603 根因）→ REQUIRED_ENV_KEYS 常量+单测
4. **dsh stderr 泄密面**（T2 发现）：启动失败时 stderr 可能含解析后 env map → 4KB 环形缓冲+消毒（键名模式 PASSWORD/TOKEN/SECRET/KEY）
5. **引擎孤儿自灭**（T9 发现）：网关死亡 → dsh 子树 1.4s stdin EOF 自退——双活窗口比设计假设更安全
6. **D14 续问历史缺口**（soak 发现2，0bab7d1 修复）：每任务新 spawn 会话零记忆，正常续问需注入——从恢复路径扩为每次执行
7. **QUOTA 错误分类缺口**（soak 发现1，0bab7d1 修复）：402 烧满 3 attempt ×15 任务=45 次无效 turn → CONFIG 快败零重试

## claudecodeui 对接清单（A1 跨仓依赖交接）

### API 契约（Bearer + X-User 双头）

```
POST /api/tasks        {question, session_id?, user?, scope_group?, client_submission_id?}
                      → 201 {run_id, session_id} | 401 | 400 | 429 RATE_LIMIT
GET  /api/tasks/:id    → {run_id, session_id, status, stage, attempt, error_code, ...}
GET  /api/tasks/:id/events   SSE：id:<seq> event:<type> data:<payload>；Last-Event-ID/??after= 重连；done 后关流
GET  /api/health       → {ok, queue_depth, running}
```

事件六类：stage / sql（含 result_ref,rows,truncated）/ answer / report / error / done（status: succeeded|failed|cancelled）。

### claudecodeui 侧改造点

1. 调用地址换网关；提问改为"提交任务+订阅 SSE"模式（client_submission_id 前端生成、重试复用）
2. 断线重连：按 seq 去重；`repairing`/`querying` 等 stage 映射前端状态文案
3. 用户身份：后端从登录态生成 X-User（不信浏览器直传）；报告静态托管 reports/<user>/ 属主校验
4. 对接验证步骤：`E2E_LIVE=1 node --test test/e2e.live.test.ts` 作为联调冒烟

### 部署要求（env 清单）
