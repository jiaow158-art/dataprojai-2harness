## 数据来源与ETL流程

```
DM.DM_RPT_GROUP_ACHIEVEMENT_AMB_T (阿米巴达成底表, 历史+原有)
  ↓ JOIN dwrfin.dwr_gl_sales_group_v (5级组织层级)
  ↓ JOIN dm.dm_rpt_bi0_tcustomer_t (客户名称)
  ↓ 渠道判定（零售/工程/大包/设计师, 基于distr_chan+zyl01+plant）
  ↓
UNION ALL
  ↓
dm.dm_rpt_sales_achievement_send_rpt_t (当日业绩底表)
  ↓ JOIN dwrfin.dwr_gl_sales_group_v
  ↓ LEFT JOIN upload.upload_achievement_history (排除已人工映射客户)
  ↓
目标体系（3级）:
  upload.upload_Sales_performance_target_pus (12月unpivot)
    → 三级月目标/年目标 + 调整数
    → 四级月目标/年目标 + 调整数
    → 五级月目标/年目标 + 调整数
  ↓
排名计算：
  三级排名: 月业绩/三级月目标（运营中心+子公司分开排）
  渠道排名: 月业绩/四级月目标（同渠道内排）
  五级排名: 月业绩/五级月目标
  年度排名: (年业绩+年调整)/年目标
```

## 渠道判定逻辑

```sql
-- 渠道分为4类：零售/工程/大包/设计师
CASE
  WHEN distr_chan='06' AND zyl01 != 'G105' THEN '工程'
  WHEN (distr_chan='06' AND zyl01='G105') 
    OR (distr_chan!='06' AND zyl01='G105' AND right(plant,2)!='80')
    OR (distr_chan='09' AND right(plant,2)='80') THEN '设计师'
  WHEN right(plant,2) != '80' OR plant IS NULL THEN
    CASE WHEN zqdzh='G103' THEN '大包' ELSE '零售' END
  WHEN right(plant,2) = '80' THEN
    CASE WHEN distr_chan='08' THEN '大包' ELSE '零售' END
END
```

## 组织层级推导

| 层级 | 来源 | 逻辑 |
|------|------|------|
| 一级 | 硬编码 | `国内营销系统` |
| 二级 | system判定 | `22000001`+非33000046→`区域运营中心`; `33000046`→`工程市场中心`; `33000030`→`大包市场中心` |
| 三级 | subcompany_big_area_name | 运营中心/子公司名（"大包市场部"→"大包市场中心"） |

| 六级 | 客户编码+名称 | sold_to |

## 已知陷阱

1. **中文列名**：所有列名均为中文
2. **金额单位是万元**：所有业绩/毛利/收入指标已除以10000
3. **日级增量**：每天只刷新前一天数据（`current_date - 1`），历史数据不变
4. **组织架构不回刷**：组织变更后历史行的三四五级不会更新
5. **新品固定为0**：`季度新品`和`年累计新品`当前为硬编码0
6. **年度排名含调整数**：`(年业绩 + 年调整) / 年目标`，月排名不含调整
7. **仅瓷砖**：硬编码 `system IN ('22000001','22000004')` + 特定 subcompany_big_area
8. **排除R开头销售组**：`sales_group NOT LIKE 'R%'`
9. **918面积剔除80工厂**：`right(plant,2) != '80'`
10. **目标来源**：使用 `upload_Sales_performance_target_pus`（48列），不是 `dm_dp_api_sales_target`
