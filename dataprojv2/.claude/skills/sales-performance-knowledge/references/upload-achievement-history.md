# 客户历史业绩映射表 — upload_achievement_history

## 表概览

| 属性 | 值 |
|------|-----|
| Schema | `upload` |
| 表名 | `upload_achievement_history` |
| 用途 | **客户→组织+线组映射表**，将客户编码映射到运营中心和渠道线组（零售/工程/大包/设计师） |
| 更新频率 | 低频（组织架构调整时更新） |
| 使用者 | `DM_RPT_CT_DEPARTMENT_SALES_PERFORMANCE_T`、`DM_RPT_REGION_PERFORMANCE_DAILY_REPORT_T` |

## 列定义

基于 ETL 脚本中实际引用的字段：

| 列名 | 类型 | 说明 |
|------|------|------|
| `客编` | varchar | 客户编码（ETL中用 `lpad(客编,10,'0')` 补齐） |
| `运营中心` | varchar | 运营中心名称 |
| `零售线组` | varchar | 零售渠道对应的线组 |
| `工程线组` | varchar | 工程渠道对应的线组 |
| `大包线组` | varchar | 大包渠道对应的线组 |
| `设计师业务` | varchar | 设计师渠道对应的业务线 |

## 核心用途

### 1. 线组映射（主用途）

将客户的渠道线组从系统默认值覆盖为人工指定的线组：

```sql
CASE a.渠道
  WHEN '零售' THEN b.零售线组
  WHEN '工程' THEN b.工程线组
  WHEN '大包' THEN b.大包线组
  WHEN '设计师' THEN b.设计师业务
END AS 五级
```

### 2. 排除已映射客户

LEFT JOIN 本表并过滤 `z.客编 IS NULL`，确保已配置客户不重复处理。

## 关联方式

```sql
-- 客户编码需要左补0到10位
lpad(客编, 10, '0') = 六级编码
-- 运营中心名称转换
CASE 运营中心 WHEN '大包市场部' THEN '大包市场中心' ELSE 运营中心 END = 三级
```

## 已知陷阱

1. **中文列名**：所有列名均为中文
2. **客户编码补齐**：ETL 用 `lpad(客编,10,'0')` 补齐后匹配
3. **名称不一致**："大包市场部" 在 ETL 中转换为 "大包市场中心"
4. **覆盖规则表**：只有配置过的客户才走人工线组映射，未配置的走系统默认
5. **影响排名**：直接影响部门/区域日报中的五级排名
